## Verified problems (each: file:line or metric, what is wrong, concrete fix)
1. Decision recommends a time the posterior and the data both contradict (main.py:414-430, decision.py:22-25; metrics.decision_checks; details.json decision). t*=4.64 lies inside the observed crossing bracket [2.0, 5.0] after the 75% cutoff, not before its lower bound. The posterior median RUL at 75% is 1.196 (details.json decision.posterior_median_rul_75), not 0 as the builder's note says. Since median RUL <= t*, the posterior gives P(T <= t*) >= 0.5 at the recommended replacement, i.e. the optimum is a replacement at which failure is more likely than not. The two checks are written as false/false, yet the headline still reads "t* = 4.64, interior: yes". Derating gain 4.4% (J 2.0995 -> 2.0062) rests on 200 draws per derate level; fig9 curves for d = 0.60-1.00 overlap within sampling noise and the plateau for t > 10 is about 10% above the optimum. Fix: write P(T <= t*) and the RUL quantiles at t* to metrics; if t* exceeds the observed bracket lower bound, set decision.optimal_value to null and state "no recommendation"; bootstrap the derating gain over 1000 draws and drop derating if its interval includes 0.
2. Design box leakage: yes, it can leak test information, and the effect is unquantified (physics_model.py:30-31 LO/HI; uq_calibration.py:17 PRIOR_SD = (HI-LO)/4). LO/HI are hard-coded with no code path that derives them, so the narrowing is neither reproducible nor fold-specific. The round-1 fits used all 15 cases, so the box was shaped by data of cases now in the setting-grouped test folds. The box is also binding: held-out fits sit on its edges. Setting fold 0 (test 3,4,10,11): Ea_R = 0.006 (LO 0), log10hA = -1.991 (LO -2). Setting fold 3 (test 5,8,14,16): log10hA = -2.000, alpha = 2.954 (HI 3), gamma = 1.0 (bound). Case folds 0 and 4 also sit on edges (details.json folds_setting/folds_case). The box therefore constrains held-out physics predictions and sets the prior widths. Fix: compute the box per fold from training-fold fits (e.g. training fit range widened by 50%, clipped to physical limits), or rerun the setting CV with the box doubled in each direction and report both results.
3. Physics fits: 2 of 4 setting folds did not converge (folds 1 and 3, nfev = 150 = max_nfev; details.json folds_setting), and 3 of 4 sit on a bound. Their physics RMSE is 0.195 and 0.230 mm; in fold 3 physics (0.230) is worse than data-driven (0.224). The pooled physics advantage (nRMSE 0.540 vs 0.874) rests on the two converged folds (RMSE 0.082 and 0.091). Estimates swing across folds: Ea_R = 0.006 / 22.7 / 141 / 0.08 and alpha = 0.004 / 1.47 / 2.95 / 0.22, so the prior centres are not identified (physics_model.py:82-100, max_nfev default 150). Fix: max_nfev >= 1000, x_scale='jac', n_starts = 8; add a converged-folds-only nRMSE next to the primary one; stop calling the prior centres "estimates" in summary.md.
4. The log-linear baseline is worse than a constant predictor, so "physics beats the baseline" (0.540 vs 1.296) is a strawman. On the same setting folds (my check, same rows as main.py): constant training-mean predictor nRMSE 1.031; time-only log-linear VB = a t^q nRMSE 0.949. The qn exponent of surrogate_model.py:61-78 is unstable across folds (p = -0.07, 0.56, 0.79, 0.12; details.json baseline) and hurts out of sample. Fix: add constant-mean and time-only baselines to run_cv (main.py:93-94) and to metrics.json; drop or regularise the qn term; compare physics and hybrid against the best simple baseline and say so in summary.md.
5. MCMC: still NOT converged, and the headline convergence ratio regressed (metrics.mcmc.min_steps_over_tau 17.5; r1 27). Chains were doubled (4500 -> 10000 post-burn), but tau rose in step: case 1 at 75% has mean tau 247.7 and min chain/tau 26.4 (details.json stages), so the longer chain bought nothing on that stage. Reaching 50 tau for the largest tau (571.6) needs about 28,600 post-burn steps, which is roughly 3x the calibration cost. Fix: reparametrise to decorrelate log10A and log10B (see fig6 corner) to cut tau; otherwise keep the NOT-met flag and state that the posteriors are approximate, as now.
6. UQ is still miscalibrated and the noise model still allows negative VB. Coverage of 50/80/95% intervals is 0.343/0.586/0.843 (metrics.interval_calibration), i.e. too narrow at 50/80 and too narrow at 95. The predictive band is additive Gaussian on VB (uq_calibration.py:44 and :90); fig4_calibration_case1 (25% panel) shows the 95% band reaching about -0.1 mm, which is r1 item 7 still open. The 50% miss at case 1 is bias, not interval width (see stage table). Fix: model noise on log VB (non-negative, heteroscedastic) and predict in log space; report signed bias per stage next to coverage.
7. Emulator cap and crossing bias are asserted, not tested (surrogate_model.py:20, :103; main.py crossing_check near line 281). The summary says the cap "does not move" crossings, but the cap was never switched off, and the emulator-vs-ODE crossing error at the prior centre is 2.06, 6.38 and 1.20 CSV units (case 11: ODE 63.1 vs GP 56.7). Separately, ODEEmulator.predict returns the lognormal mean exp(ml + 0.5 sl^2) - EPS (surrogate_model.py:91), and crossing_time uses that mean curve (uq_calibration.py:97-118). A mean curve crosses earlier than the median curve, which matches the early RUL for case 1 (median 1.20 vs observed bracket 2-5). Fix: run one ablation with VB_CAP = None and report the change in crossing times; compute crossings on the median curve exp(ml) - EPS and report both.
8. Data-driven baseline is weak and not like-for-like. DataDriven nRMSE 0.874 beats the constant-mean reference (1.031) only modestly. It uses concurrent sensor readings (smcAC, smcDC, vib, AE) and time as inputs (data_loader.py:21), which is sensing at the same instant, while the physics ODE is open-loop from VB(0) = 0. The comparison therefore favours data-driven for held-out sensing and does not test forecasting. Fix: report a forecasting variant (operating inputs + time only) next to the sensing variant, and label each in the table.
