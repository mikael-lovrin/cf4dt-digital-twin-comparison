## Verified problems (each: file:line or metric, what is wrong, concrete fix)
1. DECISION OPTIMUM IS A CLIFF, C3 PASSES BY RULE (decision.py:interior_check; main.py:340, 428-444; metrics decision/decision_checks). At 50 % life expected_cost_rate = 0.0015644427 = 1/T* exactly (1/639.2053), with P_fail_within_T_star = 0.0. Since P_fail = 0 below T*, the cost there is 1/T, which falls with T, so the argmin is the last grid point before any posterior RUL draw can fail. The same holds at 75 % (cost = 1/197.26, P_fail 0.0; RUL 95 % interval starts at 199.7) and at 25 % (P_fail 0.01; interval starts at 914, T* 894). T* sits just below the lower tail of the 400 posterior draws in every stage. The 1 % rise test is met by the jump itself (rise_after_argmin 355 %), so C3 cannot tell a cliff from a trade-off. Consequences: c_f = 5, 10, 20 all give T* = 639; the sweep range [639, 664] comes only from c_f = 2; derating_raw = 1.0 at 50 % and 75 %; risk.value = 0.0; the stressed scenario fails C4 (P = 0.0). The decision layer carries no information here. Fix: write 'no recommendation: optimum lies at the lower edge of the posterior RUL support' whenever T* < the 2.5 % quantile of conditioned RUL or P_fail(T*) < 0.05; define interior on the smooth part of the curve only; state in summary that a c_p/c_f trade-off was not found.
2. HELD-OUT RESULTS USE A TIME INDEX THAT SEES THE HELD-OUT TARGET (data_loader.py:reconstruct_pseudo_trajectory sorts all 2000 rows by VB_mm before ranking; main.py:175, 316, 323). A held-out row's time index is its rank among all rows, so it depends on its own VB. The four held-out blocks are contiguous rank ranges 400-499, 900-999, 1400-1499 and 1900-1999 (SEG_LEN=100, HOLDOUT_MOD=5), each bracketed by training rows at ranks 399/500 etc. The held-out target is therefore sandwiched between known neighbours by construction. Every held-out RMSE, the linear/RF/hybrid comparison, and the 50/80/95 coverage are interpolation tests on a monotone curve, not predictions. The summary says the time index is target-derived but does not say the held-out rows are bracketed. Fix: rank on training rows only; add a forward split (train on training ranks < 1500, predict the later training rows) and report it as the only forecast test; keep the blocked test labelled as interpolation.
3. COVERAGE PASS (C1) IS WEAK AND RESTS ON A FITTED SHRINK FACTOR (main.py:383-411). The 0.95 level is 0.905 (margin 0.005 to the 0.05 tolerance). The band is scale_c * sqrt(sigma_obs^2 + GP_sd^2) with scale_c = 0.383, fitted so that 95 % of 399 TRAIN rows beyond the 75 % stage fall inside, i.e. extrapolation residuals applied to interpolation rows. Median posterior sigma_obs = 0.0025 mm, so the band's effective noise is 0.38 * 0.0025 = 0.00096 mm. That is 2.6x smaller than the sigma_obs the likelihood uses, so the calibration and the band disagree on the noise level. The 0.006 mm width is therefore set by a post-hoc shrink, not by the model. The 0-2000 window does remove the r2 0.3 mm nugget artefact (GP sd is now 0.0009 mm), so that part of the r2 fix is real. Fix: report held-out RMSE of the calibrated posterior-median trajectory and an interval score at 50/80/95; refit sigma_obs against that residual scale (scale_c = 1) and report coverage without the fitted factor; if that fails C1, write FAIL.
4. SOBOL ON RUL IS CENSORING-DRIVEN (metrics sobol_meta: RUL_censored_frac = 0.49; uq_calibration.sobol_analysis). Half the Sobol samples have RUL = 2000 (horizon), so the RUL indices mostly measure 'crosses within the record or not'. The change from r2 (log_k2 S1 0.26 -> 0.66) is therefore not a physical sensitivity result. Also only 1538 of 4096 base rows survive the truncation. Fix: report Sobol on min(RUL, horizon) with the censored share printed next to it, or drop RUL Sobol and keep VB_end; state that RUL indices are censoring-driven.
5. PRIOR TRUNCATION IS UNTESTED AND MIS-NORMALISES THE RATIOS (main.py:315, surrogate_model VB_PRIOR_MAX=1.0, make_logp vb_max). The 1 mm cut removes 28 % of the design box, a corner of high-wear designs (the data's VB max is 0.376 mm). It is data-independent, but no sensitivity to the threshold is reported. The posterior-to-prior ratios use prior_sd = box/sqrt(12) of the untruncated box, so they are biased toward 'more learned' than the truncated prior allows. Fix: run vb_max in {0.5, 1, 2} mm and report T*, ratios, and coverage for each; compute prior_sd from the truncated sample.
6. MCMC NOT CONVERGED AND OVER-PARAMETERISED (metrics mcmc: min_steps_over_tau = 15.0, FAIL; acceptance 0.06-0.11 at 75 %). Posterior-to-prior ratios are k1 0.85 and alpha 0.78 (weakly identified); alpha has RUL Sobol S1 0.009. The label 'provisional' is honest. The DE-move mixture (r2 item) helps (mean tau 370 -> 157) but is not enough. Fix: fix alpha and fix or reparametrise k1 (sample log hA, log k2, sigma_obs only); add a MAP initialisation (scipy.optimize on -logp) before emcee; target steps/tau >= 50 with the existing 5000 steps (needs tau <= 100).
7. GP AMPLITUDE AT ITS UPPER BOUND, NOT REPORTED (surrogate_checks.gp_kernel = 31.6**2 * Matern...; run.log ConvergenceWarning 'close to the specified upper bound 1000.0'). ConstantKernel bounds are (1e-3, 1e3), and 31.6^2 = 999.6. The nugget is at its lower bound 1e-10 (NUGGET_BOUNDS[0]), which the code does not test (see claims below). Fix: normalise outputs so the amplitude is O(1), or raise the bound to 1e5, and report both bound-hit flags; no change in claims until refit.
8. OVERREACH AND MISSING R2 GROUP ITEMS (main.py:862-863 verdict v5; baselines block). 'The physics adds nothing measurable over the linear trend' is read from a leave-one-segment CI with k = 4 segments (t_3 = 3.18). The physics-minus-linear CI is [-0.0052, +0.0067] mm, roughly twice the effect size, so the test has no power: 'not distinguishable' is the correct wording. No constant-mean baseline and no interval score were added, both requested in the r2 group review. No MAP initialisation or ridge reparametrisation (r2 group item 3). Fix: reword v5 to 'not distinguishable at k = 4'; add a constant-mean baseline; add interval score at 50/80/95 to interval_calibration.
